Explanation and complete recorded results

Request 03 — Invalid amount format and expired test card
Changes made

+ "amount": 1099
- "expiry_year": 2025
+ "expiry_year": 2030
Explanation and complete recorded results
The original request returned amount_invalid because amount was supplied as 10.99. The API requires an integer amount in minor currency units. Assuming the intended payment was USD 10.99, I changed the value to 1099 cents.
The next response returned card_expired, as the supplied expiry was August 2025. I updated the sandbox test expiry year to 2030.
The final response returned approved: true, status: "Authorized" and response_code: "10000" for USD 10.99. At the time of this response, total_captured was 0, so the observed result confirms successful authorization, not capture or settlement.

Reference links
https://www.checkout.com/docs/resources/calculating-the-amount
Field clarification: the retained source quotation mentions an amount within a payment plan. For this request, the relevant field is the top-level POST /payments amount, expressed as integer minor currency units.

Request 04 — Invalid currency and unsupported payment country
Changes made

+ "currency": "EUR"

+ "source.payment_country": "BE"
Explanation and complete recorded results
The original request returned currency_invalid because "US" is not a valid three-letter currency code. I changed it to "EUR", the processing currency supported for Bancontact.
The next response returned payment_country_invalid for "DE". Checkout.com lists Belgium as Bancontact’s supported consumer country, so I changed payment_country to "BE".
The corrected request returned HTTP 202 with status: "Pending" and a redirect link. Opening the link successfully displayed the Bancontact sandbox payment page with the expected amount of EUR 1.00. This confirms that the request was accepted and the customer could proceed to the payment page. Final payment completion was not verified.
